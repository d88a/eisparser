# Исправление ошибок этапа 1–2

**Дата:** 30.01.2026  
**Статус:** к исправлению  
**Область:** Stage 1–2 (Pipeline + API/UI)

## 1) Контекст
Этап 2 формально реализован (статусы, выборки, user/admin API, UI), но текущая реализация содержит блокирующие ошибки и логические несоответствия, из‑за которых сценарии не работают в рантайме.

## 2) Критические ошибки (блокируют работу)
1. **`Pipeline` использует `self.db_service`, которого нет**
   - Файл: `src/pipeline.py`
   - Симптом: `AttributeError: 'Pipeline' object has no attribute 'db_service'` при обновлении статусов.
   - Исправление: использовать `self.db` (экземпляр `DatabaseService`) вместо `self.db_service`.

2. **API эндпоинты обращаются к `pipeline.db_service`, которого нет**
   - Файл: `src/api/routes.py`
   - Симптом: `AttributeError` на всех user/admin эндпоинтах.
   - Исправление: заменить `pipeline.db_service` на `pipeline.db`.

3. **Неверный метод репозитория AI**
   - Файл: `src/api/routes.py`
   - Симптом: `AttributeError: AIResultRepository has no attribute get_result`.
   - Исправление: использовать `pipeline.db.ai_results.get_by_id(...)` или `pipeline.ai.get_result(...)`.

4. **Дублирование кода этапа 2**
   - Файл: `src/api/routes.py`, `src/api/new_routes_stage2.py`
   - Риск: расхождение логики и баги при правках.
   - Исправление: оставить один источник правды (встроить код в `routes.py`, `new_routes_stage2.py` убрать или явно пометить как архив).

## 3) Логические несоответствия
1. **Статус `user_selected` нигде не устанавливается**
   - Сейчас выборки пользователя живут только в `user_selections`.
   - Решение: либо убрать `user_selected` из жизненного цикла статусов, либо обновлять `zakupki.status` при select/unselect.

2. **Stage 4 может запускаться автоматически через `process_zakupka()`**
   - Файл: `src/pipeline.py`
   - По умолчанию `run_stage4=True` нарушает правило ручного gate.
   - Решение: дефолт `run_stage4=False`, либо запретить вызов в пользовательском контуре.

## 4) Требуемые исправления (минимальный план)
1. Исправить обращения `db_service -> db` в `src/pipeline.py` и `src/api/routes.py`.
2. Исправить `get_result -> get_by_id` в API.
3. Убрать/архивировать `src/api/new_routes_stage2.py` (или синхронизировать и документировать, какой файл используется).
4. Определиться со статусом `user_selected` и закрепить это в API и документации.
5. Зафиксировать ручной запуск Stage 4 (по умолчанию не запускать).

## 5) Чек‑лист проверки после исправлений
- `GET /api/user/available_zakupki` отдаёт список `url_ready` без ошибок.
- `POST /api/user/select` добавляет выборки.
- `GET /api/user/selections` возвращает данные с AI‑полями.
- `POST /api/user/run_stage4` запускает сбор объявлений и обновляет `listings_fresh`.
- `GET /api/admin/pipeline_status` возвращает статистику.
